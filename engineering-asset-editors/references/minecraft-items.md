# Minecraft 物品与动态图标

只在编辑器接入 MC 物品、源码资源或动态贴图时阅读。版本相关事实先对照目标模组的注册、客户端模型映射与资源文件，不把其他 MC 版本的机制直接套入。

## Item 身份不等于 Java 文件

在 1.12.2，一个 Java 类和注册 ID 常管理多个 metadata 变体。具体物品身份通常需要注册 ID、metadata，必要时加 NBT。相同类的不同变体可以有不同名称、模型与贴图，不能按“一份 Java 文件生成一个 Item”导入。

普通物品的展示链通常是：注册身份与 metadata → 客户端模型映射 → 模型 JSON → PNG；语言文件提供名称。方块物品、火箭或特殊渲染物品可能不是一张平面 PNG。若编辑器只支持图标，明确它是展示近似，不声称复现游戏渲染。

## PNG 帧图与 mcmeta

MC 1.12 的常见动画贴图是纵向堆叠的正方形帧图，旁边有同名的 `name.png.mcmeta`。先以目标版本实现为准；格式入口可参考 [Forge 1.12 模型文件说明](https://docs.minecraftforge.net/en/1.12.x/models/files/)。

```json
{
  "animation": {
    "frametime": 3,
    "interpolate": true,
    "frames": [0, 1, {"index": 2, "time": 6}, 1]
  }
}
```

- 一个 tick 为 50 ms；默认 `frametime` 为 1。整数帧项沿用默认时长，对象帧项可指定自己的 `time`。
- 未指定或未列出帧序列时按帧图顺序循环；保留重复索引和自定义顺序。
- 帧索引、时长、尺寸与图像分割必须合法；配置错误时保留旧图标，提示具体原因。
- `interpolate` 表示相邻帧间插值，不是仅将整张长图缩成一个小图标。
- 只绑定 PNG 时，是否自动推断竖向帧图，是编辑器的便捷策略，不是“没有 mcmeta 的 MC 也一定会播放”。若采用此策略，在用法中说明。

## 显示与保存

图标绑定入口遵循当前目录约定；支持同时选择 PNG 和配套 mcmeta，也可给已绑定图片补充元数据。不要因补了动画功能，就在工作区、最近栏和属性面板到处新增绑定入口。

将图片和动画配置分开保存，例如 `icon` 使用图片 data URL、`iconAnimation` 保留元数据；API、工程导入与页面对可选值和无效值保持一致。

共享同一 Item 的解码结果、帧状态与插值缓存，单次推进后供目录、槽位、最近栏、属性、配方预览及鼠标拿取图标使用。保持像素清晰，在页面隐藏时暂停不必要重绘，不为每个图标建立独立定时器。静态图标仍走普通图片展示。

检查真实帧图的单帧尺寸、帧顺序、单帧时长、循环、插值、配置非法时的恢复、工程重载和拖动中播放。静态截图不能证明播放正确；至少核对两个时刻的实际画面或帧状态。MC 原始素材属于项目或第三方资源，不顺手打包进通用 Skill。
